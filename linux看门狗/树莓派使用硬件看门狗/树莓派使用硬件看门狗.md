# 1、要让 Raspberry Pi 5 的 watchdog 工作，需要 **开启 pcie-pwdt**

编辑：

```bash
sudo nano /boot/firmware/config.txt
```

添加这行：

```
dtparam=pcie_pwrwdt=on
```

现在 config.txt 里应包含：

```
dtparam=watchdog=on
dtparam=wdt-reset=on
dtparam=pcie_pwrwdt=on
```

保存 → 重启：

```bash
sudo reboot
```

---

# 2、 重启后检查驱动

运行：

```bash
lsmod | grep -E "wdt|pwdt"
```

你应该看到：

```
raspberrypi_pcie_pwdt
# 或没有
```

再看 dmesg：

```bash
sudo dmesg | grep -i wdt
```

应该看到：

```
bcm2835-wdt: Poweroff handler already present!
bcm2835-wdt: Broadcom BCM2835 watchdog timer
```

# 3、 最可靠的测试方法（不用破坏系统）

运行：

```bash
sudo bash -c "echo 1 > /dev/watchdog"
```

然后 **什么都不要做**。

如果 watchdog 是真的，会在大约 **15 秒 ~ 60 秒** 后强制重启。

如果不会重启，说明 watchdog 只是“假开启”，还需要进一步配置。

⚠️ 测试前确保你没有运行 watchdog.service，否则它会自动喂狗。

检查：

```bash
systemctl status watchdog
```

如果是绿色 active，我们先停止测试：

```bash
sudo systemctl stop watchdog
```

然后再执行测试命令。

# 4、 设置树莓派自动喂狗 
# 树莓派硬件 Watchdog 配置与测试

## 1️⃣ 硬件与系统支持

* 树莓派 5 内置 **Broadcom BCM2835 Watchdog Timer**
* 设备节点：`/dev/watchdog` 或 `/dev/watchdog0`
* 驱动：`bcm2835-wdt`
* 系统默认不会自动使用，需要通过 systemd 或 watchdog 服务启用

---

## 2️⃣ 推荐方式：systemd RuntimeWatchdog

* **不推荐**安装 `watchdog.service`，因为：

  * 会尝试独占 `/dev/watchdog` 与 systemd 冲突
  * 启动时可能卡住
* **官方推荐**方式：systemd RuntimeWatchdog

  * 在 `/etc/systemd/system.conf` 中启用：

    ```
    [Manager]
    RuntimeWatchdogSec=10
    ```
  * 单位：秒（timeout=10 秒比较安全）
* systemd 会自动喂狗，保证系统死锁或卡死时硬件看门狗能触发重启

---

## 3️⃣ 配置与启用步骤

1. **编辑 system.conf**

```bash
sudo nano /etc/systemd/system.conf
```

修改或添加：

```
RuntimeWatchdogSec=10
```

2. **重启系统生效**

```bash
sudo reboot
```

3. **验证硬件 watchdog**

```bash
sudo journalctl -b | grep watchdog
cat /sys/class/watchdog/watchdog0/timeout
```

* 应显示：

  ```
  Hardware watchdog 'Broadcom BCM2835 Watchdog timer', device /dev/watchdog0
  timeout = 10
  ```

---

## 4️⃣ 测试硬件 watchdog

由于 systemd RuntimeWatchdog 已锁定 `/dev/watchdog0`：

* 用户态无法直接写 `/dev/watchdog0`
* 临时 service 无法触发 watchdog

✅ 官方安全测试方式：

```bash
echo c | sudo tee /proc/sysrq-trigger
```

* 触发内核 panic
* systemd RuntimeWatchdog 在 10 秒内触发硬件 watchdog
* 树莓派自动重启
* systemd 接管后系统恢复正常

**测试结果说明**：硬件 watchdog 功能正常，可在系统挂死时自动重启

---

## 5️⃣ 注意事项

* 不要同时启用 `watchdog.service` 和 systemd RuntimeWatchdog
* 用户态写 `/dev/watchdog0` 会被拒绝，这是 systemd 正常保护机制
* 调整 timeout 时，可在 system.conf 中修改 `RuntimeWatchdogSec`
* 可搭配 `RebootWatchdogSec` 设置防止误触发重启

---

## 6️⃣ 总结

* 树莓派硬件 watchdog 已经启用并受 systemd RuntimeWatchdog 管理
* 10 秒超时可以保证系统死锁或 kernel panic 时自动重启
* 安全可靠，无需额外 daemon
* 测试方法：内核 panic (`echo c > /proc/sysrq-trigger`)
* 用户态无法直接触发 watchdog 是正常现象
