# 🧭 一、总体流程（先建立全局认知）

东山派（RK3576）这条链路是：

```text
运行中的设备树 → 导出 → 修改 watchdog → 编译 dtb → 替换 boot dtb → 重启验证 → 用户态配置 watchdog
```

核心分两段：

### ✅ 阶段1：开启硬件（DTB）

### ✅ 阶段2：使用硬件（/dev/watchdog）

---

# 🔧 二、阶段1：反编译 + 修改设备树

---

## ✅ Step 1：导出当前正在使用的设备树（最关键）

```bash
dtc -I fs -O dts -o current.dts /proc/device-tree
```

👉 这是“当前生效版本”，不是猜的

---

## ✅ Step 2：定位 watchdog 节点

```bash
grep -i watchdog current.dts
```

一般会看到类似：

```dts
watchdog@xxxx {
    compatible = "snps,dw-wdt";
    status = "disabled";
};
```

---

## ✅ Step 3：修改为启用

```dts
status = "okay";
```

必要时可以加（可选）：

```dts
timeout-sec = <10>;
```

---

## ⚠️ Step 4：确认 boot 使用的 dtb（非常关键）

东山派通常是：

```bash
/boot/dtb/rockchip/rk3576-100ask-dshanpi-a1.dtb
```

建议确认：

```bash
cat /boot/extlinux/extlinux.conf
```

看有没有：

```text
FDT /dtb/rockchip/rk3576-100ask-dshanpi-a1.dtb
```

---

## ✅ Step 5：备份原 dtb（必须）

```bash
cp /boot/dtb/rockchip/rk3576-100ask-dshanpi-a1.dtb \
   rk3576-100ask-dshanpi-a1.dtb.bak
```

---

## ✅ Step 6：反编译原 dtb（不要直接用 current.dts）

```bash
dtc -I dtb -O dts -o dshanpi.dts rk3576-100ask-dshanpi-a1.dtb.bak
```

👉 在这个文件里改 watchdog

---

## ✅ Step 7：重新编译 dtb

```bash
dtc -I dts -O dtb -o rk3576-100ask-dshanpi-a1.dtb dshanpi.dts
```

---

## ✅ Step 8：替换 dtb

```bash
cp rk3576-100ask-dshanpi-a1.dtb /boot/dtb/rockchip/
```

---

## ✅ Step 9：重启

```bash
reboot
```

---

```bash

```

---

## ✔️ 3. dmesg（可能没有明显日志，RK常见）

```bash
dmesg | grep -i watchdog
```

# ⚙️ 四、阶段2：使用 watchdog（核心）

---

## 🧠 基本原理

| 操作        | 含义                  |
| --------- | ------------------- |
| 第一次 write | 启动 watchdog         |
| 后续 write  | 喂狗                  |
| 不喂        | 超时 → reboot         |
| 写 "V"     | 关闭 watchdog（有些平台无效） |

---

## ✅ Step 1：启动 watchdog

```bash
echo 1 > /dev/watchdog
```

---

## ✅ Step 2：测试自动重启（验证）

```bash
echo 1 > /dev/watchdog
sleep 30
```

👉 不再喂狗 → 应该自动 reboot

# 📦 五、安装 watchdog 服务（标准流程）

---

## ✅ Step 1：安装软件包

```bash
apt update
apt install watchdog
```

---

## ✅ Step 2：确认服务是否存在

```bash
systemctl status watchdog
```

或者：

```bash
systemctl list-unit-files | grep watchdog
```

正常会看到：

```text
watchdog.service
```

---

# ⚙️ 三、核心配置文件

---

## 📄 配置文件位置

```bash
/etc/watchdog.conf
```

---

## ✅ 基本推荐配置（适合 RK 板子）

编辑：

```bash
nano /etc/watchdog.conf
```

写入或修改：

```conf
# 使用硬件看门狗设备
watchdog-device = /dev/watchdog

# 超时时间（秒）
watchdog-timeout = 16

# 刷新间隔（秒）
interval = 5

# 使用 settimeout 刷新方式
watchdog-refresh-use-settimeout = yes

# 前台实时优先级
realtime = yes
priority = 1
```

# ⚠️ 七、非常重要的坑（RK 板子必看）

---

## ❗坑1：不要和手动 echo 冲突

如果 watchdog.service 在跑：

👉 你再 `echo 1 > /dev/watchdog` 可能会：

* 触发 reset
* 或干扰 daemon

---

## ❗坑2：timeout 不一致问题

你 DTB / kernel / watchdog.conf 可能三套 timeout：

| 来源             | 优先级 |
| -------------- | --- |
| DTB            | 高   |
| kernel default | 中   |
| watchdog.conf  | 用户态 |

👉 最终以 **kernel + driver 为准**

---

## ❗坑3：systemd 自带 watchdog（可选更高级）

你还可以不用 watchdog daemon，而是：

```ini
RuntimeWatchdogSec=10
```

在：

```bash
/etc/systemd/system.conf
```

👉 这是 systemd 直接喂 kernel watchdog（更轻）

---

# 🧠 八、两种方案对比（重点）

| 方案                      | 复杂度 | 推荐度  | 说明      |
| ----------------------- | --- | ---- | ------- |
| watchdog.service        | 中   | ⭐⭐⭐  | 灵活，可做监控 |
| systemd RuntimeWatchdog | 低   | ⭐⭐⭐⭐ | 工业推荐    |
| 手动 echo                 | 低   | ❌    | 测试用     |

---

# 🚀 九、推荐你用哪种？

结合你在做 ROS2 + robot：

👉 最推荐：

```text
systemd RuntimeWatchdogSec + ROS2 heartbeat
```

理由：

* 少一个进程
* 更稳定
* 启动早（PID1级别）

# 🎯 十、一句话总结

安装 watchdog.service 的本质是：

> 🟢 让用户态进程定时喂 /dev/watchdog
> 🟢 从“手动测试”升级为“系统自动防死机机制”

---

## ⚠️ 注意点（你已经踩过）

### ❗ `cat /dev/watchdog` 会报错（正常）

### ❗ `echo V > /dev/watchdog` 是关闭 watchdog

### ❗ RK 平台可能：

* 不支持关闭（did not stop）
* 不提供 timeleft/sysfs

# 🚀 十二、工程化建议（强烈推荐）

现在你只是“能用”，但还不够稳，建议加一层控制：

---

## ✔️ 方案1：systemd watchdog（推荐）

编辑：

```bash
/etc/systemd/system.conf
```

```ini
RuntimeWatchdogSec=10
```

---

## ✔️ 方案2：ROS2 喂狗线程

* 1~2 秒 heartbeat
* 主线程死 → 不喂 → 自动重启

---

## ✔️ 方案3：独立 watchdog 守护进程

避免业务代码直接操作 `/dev/watchdog`
