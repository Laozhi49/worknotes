# 脚本
```bash
#!/bin/bash
PATH_PWD="$(dirname "$(realpath "${BASH_SOURCE[0]}")")"

creat_lnk() {
    local name=$1
    local link_path="/usr/bin/${name}"
    local link_file_name="tools/${name}.sh"
    if [ -L $link_path ]; then
        rm ${link_path}
    fi
    ln -s ${PATH_PWD}/$link_file_name ${link_path}
}

creat_lnk npu-model-export
creat_lnk npu-model-generate
creat_lnk npu-tool
creat_lnk npu-transfer-yolo
```

---

## 一句话先给结论

> **因为你把软链接放到了 `/usr/bin`，而 `/usr/bin` 在 `$PATH` 里**

所以无论你当前在哪个目录，shell 都能找到它。

---

## 一、Linux 执行命令时到底发生了什么？

当你在终端敲：

```bash
npu-transfer-yolo
```

**shell 并不是“当前目录找”**，而是按这个顺序：

### 1️⃣ 是否是内建命令（如 `cd`）

不是 → 继续

### 2️⃣ 是否是绝对 / 相对路径

```bash
./npu-transfer-yolo
/path/to/npu-transfer-yolo
```

你没有 → 继续

### 3️⃣ 在 `$PATH` 里的目录依次查找

```bash
echo $PATH
```

你一定会看到类似：

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

📌 **`/usr/bin` 就在这里**

---

## 二、你这段脚本到底干了什么（逐行拆）

### 1️⃣ 定位脚本所在目录（关键点）

```bash
PATH_PWD="$(dirname "$(realpath "${BASH_SOURCE[0]}")")"
```

含义：

* `${BASH_SOURCE[0]}` → 当前脚本文件
* `realpath` → 转成绝对路径
* `dirname` → 取目录

👉 **无论你从哪里执行这个脚本，它都知道自己在哪**

---

### 2️⃣ 创建软链接函数

```bash
creat_lnk() {
    local name=$1
    local link_path="/usr/bin/${name}"
    local link_file_name="tools/${name}.sh"
```

意思是：

* 最终执行的“命令名”：`npu-transfer-yolo`
* 实际脚本在：

  ```text
  ${PATH_PWD}/tools/npu-transfer-yolo.sh
  ```

---

### 3️⃣ 删除旧链接

```bash
if [ -L $link_path ]; then
    rm ${link_path}
fi
```

只删除**软链接本身**

---

### 4️⃣ 创建软链接（核心）

```bash
ln -s ${PATH_PWD}/$link_file_name ${link_path}
```

实际效果：

```text
/usr/bin/npu-transfer-yolo
   ↓
/absolute/path/to/your/project/tools/npu-transfer-yolo.sh
```

---

## 三、为什么不用管当前目录？

因为你现在的命令结构是：

```text
/usr/bin/npu-transfer-yolo  →  /xxx/tools/npu-transfer-yolo.sh
```

而：

* `/usr/bin` 在 `$PATH`
* shell 找到的是 `/usr/bin/npu-transfer-yolo`
* Linux 自动 **跟随软链接**
* 执行的是目标脚本

📌 **执行的是目标文件，不是软链接本身**

---

## 四、为什么它看起来“像系统命令”？

你已经做了三件系统级的事：

1️⃣ 链接放在 `/usr/bin`
2️⃣ 名字没有 `.sh` 后缀
3️⃣ 脚本里很可能有：

```bash
#!/bin/bash
```

👉 所以 shell 会把它当作：

```text
一个合法的可执行程序
```

---

## 五、必须满足的 3 个隐藏条件（很重要）

### ✅ 1. 目标脚本必须可执行

```bash
chmod +x tools/npu-transfer-yolo.sh
```

否则会报：

```text
Permission denied
```

---

### ✅ 2. 脚本首行必须是 shebang

```bash
#!/bin/bash
```

否则会：

```text
Exec format error
```

---

### ✅ 3. `/usr/bin` 必须在 `$PATH`

一般 Linux 默认就有。

---

## 六、你现在这种方式，本质是什么？

> **你在“手动实现 apt install 的命令注册机制”**

几乎等价于：

```bash
apt install npu-tool
```

只不过是你自己维护。

---

## 七、一个很重要的工程级建议（进阶）

### ❌ 不推荐直接写 `/usr/bin`

更安全的做法：

```bash
~/.local/bin
```

```bash
mkdir -p ~/.local/bin
ln -s xxx ~/.local/bin/npu-transfer-yolo
```

并确保：

```bash
export PATH="$HOME/.local/bin:$PATH"
```

📌 好处：

* 不用 sudo
* 不污染系统
* Docker / WSL / CI 更安全

---

## 八、总结一句话

> **你之所以能在任何目录直接执行 `npu-transfer-yolo`，不是因为软链接神奇，而是因为你把它放进了 `$PATH`，而软链接只是“指向真正脚本的跳转入口”。**
